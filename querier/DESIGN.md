# CS50 TSE Querier
## Design Spec
## Mithun Rameshkumar May 2025

According to the [Querier Requirements Spec](REQUIREMENTS.md), the TSE *querier* is a standalone program that takes an index file generated by the *indexer* and enables users to search the documents stored in the `pageDirectory` for specific words or phrases. It supports AND and OR operators to fine-tune search criteria, and outputs a list of documents ranked by how closely they match the query. 

### User Interface

The querier's interaction with the user is initiated via the command-line and requires three arguments:

```
./querier pageDirectory indexFilename
```

For example, if `letters10` is a pageDirectory in `../data` and `letters10` is the corresponding index file in ``../data/indexes:

```bash
$ ./querier ../data/letters10  ../data/indexes/letters10
```

After initialization the querier prompts the user to enter search queries.

```
$ ./querier ../data/letters10 ../data/indexes/letters10
Query? school
Query:  school
No documents match.
Query? for
Query:  for
Matches 9 documents (ranked):
score   1  doc  1: http://cs50tse.cs.dartmouth.edu/tse/letters/index.html
score   1  doc  2: http://cs50tse.cs.dartmouth.edu/tse/letters/A.html
score   1  doc  3: http://cs50tse.cs.dartmouth.edu/tse/letters/B.html
score   1  doc  4: http://cs50tse.cs.dartmouth.edu/tse/letters/E.html
score   1  doc  5: http://cs50tse.cs.dartmouth.edu/tse/letters/G.html
score   1  doc  6: http://cs50tse.cs.dartmouth.edu/tse/letters/H.html
score   1  doc  7: http://cs50tse.cs.dartmouth.edu/tse/letters/F.html
score   1  doc  8: http://cs50tse.cs.dartmouth.edu/tse/letters/D.html
score   1  doc  9: http://cs50tse.cs.dartmouth.edu/tse/letters/C.html
```

### Inputs and outputs

**Input**: 
 - Index file: A directory path to the index file, which the querier loads into memory as its search index.
 - Crawler files directory: A directory path pointing to the set of crawler-generated files (the pageDirectory).
 - User query: Read from standard input, the querier validates and tokenizes the query string, interpreting AND and OR operators.

**Outputs**:
 - Search results: A list of documents sorted by relevance score. Each line shows:
    1. The document's score
    2. The document ID
    3. The document URL
    - No matches: If the query yields no hits, a "no documents found" message is printed.

**Scoring Rules**:
- Single term: Score = count of that word's occurrences in the document
- AND expressions: Score = the minimum occurrence count among all terms
- OR expressions: Score = the sum of each term's occurrence count
- Complex queries: Evaluate all AND subexpressions without combining results with OR operators.

### Function Decomposition into Modules

The querier is divided into several primary functions and modules:
1. *main*: calls parseArgs, loads the index via index_save, runs getQueries, then cleans up.
2. *getQueries*: prompts via prompt, reads stdin, tokenizes, scores with identifyDocuments, prints ranked hits.
3. *tokenize*: splits input on whitespace, lowercases via word module, and enforces valid AND/OR usage.
4. *identifyDocuments*: builds two counters_t* (AND segment and OR union) and returns final scores per docID.
5. *index*: loads (index_save) and queries (index_find) the inverted index built by the indexer.
6. *counters*: maps docIDs to scores; supports new, iterate, get, set, and delete operations.

And the helper functions/modules:

7. *parseArgs*: ensures two args (pageDirectory, indexFilename), checks for /.crawler and at least one page file, and verifies the index file.
8.	*prompt*: prints "Query? " only when stdin is a terminal (using isatty).
9.	*getMax*: used by counters_iterate to find the document with the highest score and its docID.
10.	*counterSize*: used by counters_iterate to count how many entries have non-zero scores.
11.	*andIterate*: merges two counters for AND by setting each key’s count to the minimum of its values.
12.	*getMin*: returns the lesser of two integers (helper for andIterate).
13.	*copyIterate*: copies all (docID, count) pairs from an index’s counter into a new conj counter.
14.	*orIterate*: merges two counters for OR by summing counts for each key.

### Pseudocode for logic/algorithmic flow

The querier will run as follows:


1. main
	-	Parses and validates pageDirectory and indexFilename.
	-	Opens the index file, builds the index with index_save, then closes it.
	-	Calls getQueries to start the interactive loop.
	-	After returning, deletes the index and exits with success.

2. getQueries
	-	Prints Query?  if stdin is a TTY, then reads each input line.
	-	Tokenizes with tokenize, re-prompts immediately on error.
	-	Echoes cleaned tokens as Query: … and calls identifyDocuments.
	-	Counts matches via counterSize; prints “Matches N documents (ranked):” or “No documents match.”
	-	In a loop, finds top score/doc via getMax, reads its URL, prints score …  doc …: …, zeros that score.
	-	Frees token array and counters, prints a separator, then re-prompts.

3. tokenize
	-	Scans for non-alphabetic/non-whitespace chars; on any error prints a message and returns NULL.
	-	Counts spaces, allocates an array, then splits on whitespace with strtok.
	-	Lowercases each token via word_normalize.
	-	Rejects if first/last token is and/or or if two operators are adjacent, printing an error.
	-	On success, sets *numTokens and returns the token array.

4. identifyDocuments
	-	Starts with conj = NULL (current AND) and total = NULL (OR union).
	-	For each token:
	    1.	Skip “and.”
	    2.	On “or”: if total is empty, assign conj→total; else merge via orIterate; then conj = NULL.
	    3.	On word: if in index, create or intersect conj via copyIterate or andIterate; if missing, delete conj.
	-   After all tokens, return conj if no OR seen; otherwise merge any remaining conj into total and return total.

5. Score Combination Helpers
	-	andIterate: for each doc in conj, set its count to the minimum of its old value and the new word’s count (or zero).
	-	orIterate: for each doc in conj, add its count to total, inserting it if absent.
	-	getMin: returns the smaller of two counts.
	-	copyIterate: copies each key and its count into a fresh conj.

### Major Data Structures

The querier primarily uses the following data structures:
- *index*: Maps words to counters of document IDs and word counts.
- *counters*: Tracks document IDs and scores for the current query. 

### Testing plan

*Unit Testing*: The *testing.sh* script will include tests for the *querier* by running it with various invalid and valid queries.

1. Run *querier* with various invalid arguments.
    1. No arguments
    2. One argument
    3. Three arguments
    4. Invalid pageDirectory
    5. No .crawler file
    6. No files to read
    7. Invalid indexFile
2. Run *querier* with a valid argument and enter both valid and invalid queries to check for correct output.
3. Run *valgrind* on *querier* to check for memory leaks.
